# GameShorts

Inshorts-style, 60-word news site for the video game industry — Pinterest-style masonry grid for discovery/SEO, with a full-screen swipeable reader layered on top. See [CLAUDE.md](./CLAUDE.md) for the full product spec.

## Stack

- **Frontend:** Next.js 16 (App Router, TypeScript), Tailwind CSS v4, dark-default design system
- **Data:** static JSON (`data/cards.json`), generated by the ingestion pipeline and read via ISR — no app database for content
- **Engagement:** Supabase (likes), Giscus (comments)
- **Ingestion:** GitHub Actions cron (`.github/workflows/ingest.yml`) → RSS → Claude API summarization → `data/cards.json`

## Getting started

```bash
pnpm install
cp .env.example .env.local   # fill in what you have; see below
pnpm dev
```

The site works with **zero env vars configured** — it falls back to a bundled mock dataset (`src/lib/mock-cards.ts`) whenever `data/cards.json` doesn't exist yet, and likes/comments degrade to static, non-interactive displays whenever Supabase/Giscus aren't configured. Nothing breaks; features just activate as you wire in real credentials.

See `.env.example` for every variable the project uses and which phase/feature each one unlocks.

## Ingestion pipeline

Runs on its own 2-hour cron via GitHub Actions, or manually:

```bash
pnpm ingest
```

Summarizes/classifies/clusters against a local Ollama instance (no API key — install Ollama and run `ollama serve` locally; the GitHub Actions workflow installs and starts it automatically). `pnpm ingest` runs the whole thing sequentially in one process for local dev; in CI it's split across 3 jobs (fetch candidates -> classify in a 4-way parallel matrix -> merge/cluster/publish) so a 2-hour cron run doesn't take as long as one runner working through every candidate serially — see the comment at the top of `.github/workflows/ingest.yml`. Both paths share the same logic under `scripts/ingest/lib/`. Writes `data/cards.json` + `data/seen.json` (dedup history); the workflow commits both, which is what actually triggers a redeploy (a full rebuild, not just ISR revalidation, is required for brand-new card slugs). Required repo secrets/variables are documented in the workflow file.
